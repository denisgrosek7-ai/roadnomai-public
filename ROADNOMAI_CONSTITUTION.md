# ROADNOMAI CONSTITUTION

## Core Directive

## 1. System Definition

RoadNomai transforms vague user intent into structured, executable, and multimodal multi-day itineraries through AI-assisted interpretation and clearly defined geographic and operational constraints.

## 2. Core Operational Logic

### Input

- Intent
- Constraints
- Preferences

### Process (Iterative)

- AI-assisted interpretation of user intent
- generation of candidate routes or nodes
- geographic, temporal, and physical validation
- synthesis of a coherent multi-day itinerary

### Output

A logical and executable sequence of nodes that may include roads, ferries, and other modes of movement.

## 3. Role of AI (Gemini)

Gemini acts as an intent interpreter and selection assistant, not as the final decision-maker.

The core system performs deterministic validation to prevent hallucinations and to ensure that route output remains realistic and physically executable.

## 4. Decision Principle

**AI proposes. The system decides.**

## Why This Matters

This is not a marketing text.  
This is not overengineering.

This is an operational document that can be used to:

- refactor code
- reject a feature
- explain the system to another developer
- extend the platform to flights, trains, and new domains

Previous work such as **Island Selection**, **Mainland Normalization**, and **Legal Pages** should not be treated as side work, but as foundational building blocks of the RoadNomai decision engine.
